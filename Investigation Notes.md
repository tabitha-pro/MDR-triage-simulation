# MDR Investigation Notes

## 1. Investigation Overview
This investigation was initiated following an automated Splunk alert triggering on suspicious PowerShell process creation telemetry on a Windows endpoint. The purpose of this investigation is to evaluate whether the detected PowerShell execution represents an unauthorized attempt to evade system defense controls, execute arbitrary payloads, or establish persistence.

- **Incident Reference:** `INC-2026-1059`
- **Primary Focus:** Suspicious PowerShell execution with policy bypass arguments (`-ExecutionPolicy Bypass`, `-NoProfile`)
- **Investigation Scope:** Host context, parent-child process hierarchy, user context, and secondary network telemetry within a +/- 30-minute window.

---

## 2. Splunk Detection Results
Telemetric evidence ingested into Splunk Enterprise via Sysmon Operational Logs (`WinEventLog:Microsoft-Windows-Sysmon/Operational`) captured the following forensic artifacts:

- **Sysmon Event ID:** `1` (Process Creation)
- **Host Context:** `Lab-Windows-Vic`
- **User Account:** `LAB-WINDOWS-VIC\SOCAnalyst`
- **Process Executable:** `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`
- **Executed Command Line:**  
  `powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "Write-Host 'MDR Simulation Test - Executing payload check'; Start-Sleep -Seconds 2"`
- **Parent Process:** `cmd.exe` (or interactive shell session)
- **Process ID (PID):** Captured and logged for process lifecycle correlation

---

## 3. Analyst Findings
A thorough Tier 1 and Tier 2 triage of the ingested telemetry yielded the following findings:

1. **Process Relationship Analysis:**
   - PowerShell was spawned interactively via command line.
   - No high-risk parent processes (such as `winword.exe`, `excel.exe`, or `w3wp.exe`) were observed launching PowerShell.

2. **Payload & Execution Evaluation:**
   - The command line contained explicit policy suppression flags (`-NoProfile` and `-ExecutionPolicy Bypass`).
   - The executed command string was evaluated as a benign simulation payload (`Write-Host` test string followed by `Start-Sleep`).
   - No obfuscated, base64-encoded strings (`-EncodedCommand`), dynamic expressions (`IEX`), or remote script downloads (`Invoke-WebRequest`) were detected.

3. **Network & File System Telemetry:**
   - Querying Sysmon Event ID 3 (Network Connection) confirmed **zero outbound C2 or external network connections** generated by this specific PowerShell process ID.
   - Querying Sysmon Event ID 11 (File Create) indicated no malicious payload drops, administrative script creation, or persistence mechanisms written to disk.

---

## 4. Incident Classification
- **Final Classification:** **Benign Positive** (Authorized / Controlled Simulation)
- **Supporting Evidence:**  
  The detection rule accurately identified the execution of PowerShell with policy bypass flags (`-ExecutionPolicy Bypass` and `-NoProfile`). However, contextual analysis confirms the activity was a controlled, benign MDR threat simulation test conducted in an authorized lab environment. No threat actor activity, system compromise, or data exfiltration occurred.

---

## 5. Lessons Learned & Detection Engineering
1. **Detection Tuning:**  
   - While `-ExecutionPolicy Bypass` is frequently utilized in malicious execution chains, it is also common in administrative automation.
   - Future detection iterations should incorporate parent process contextual filtering and anomaly scoring rather than relying solely on command-line string matching.

2. **Investigation Efficiency:**  
   - Correlating Sysmon Event ID 1 (Process Creation) with Event ID 3 (Network Connections) using `ProcessGuid` enabled rapid verification that no external network traffic occurred.

3. **Future Threat Hunting Opportunities:**  
   - Develop targeted threat hunts for unquoted expression execution (`IEX`/`Invoke-Expression`) and encoded commands (`-e`, `-enc`) originating from standard non-administrative user accounts.
